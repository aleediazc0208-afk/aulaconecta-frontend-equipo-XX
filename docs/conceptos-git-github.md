1. ¿Qué puede hacer Git aunque GitHub no exista?

Git puede registrar los cambios de un proyecto, crear versiones, recuperar trabajos anteriores y organizar el historial directamente en un computador. GitHub solo sirve para compartir el repositorio y facilitar el trabajo colaborativo por Internet.

2. ¿Por qué una rama reduce el riesgo de dañar main?

Porque permite desarrollar o modificar archivos en una copia de trabajo sin afectar la versión principal del proyecto. De esta manera, los cambios pueden revisarse y corregirse antes de integrarlos a main.

3. ¿Qué diferencia existe entre guardar un archivo y crear un commit?

Guardar un archivo solo almacena los cambios en el computador o en el editor de texto. En cambio, un commit registra esos cambios en el historial de Git con un mensaje que explica qué se hizo, permitiendo llevar un seguimiento del proyecto.

4. ¿Por qué un Pull Request no es lo mismo que un Merge?

Un Pull Request es una solicitud para que los cambios de una rama sean revisados antes de unirse a la rama principal. El Merge ocurre después de la revisión y es el proceso que integra definitivamente esos cambios en main.

5. ¿Qué evidencia permite saber quién cambió algo y por qué?

La evidencia la proporciona el historial de commits del repositorio. Cada commit muestra quién realizó el cambio, cuándo lo hizo y el mensaje que explica el propósito de esa modificación.
